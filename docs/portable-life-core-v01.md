# Mi Mundo life core: portable multi-person foundation (review only)

**Product**: A reusable personal/household operating system, not a copy of a specific person's Drive folder structure. Modules are optional: general personal records, food, health, family/schedules, assets and business. Nothing in this branch is an authorised live migration or deployed service.

**Storage separation**: PostgreSQL owns operational record state, provenance, jobs, retries and Inbox metadata; encrypted private object storage owns exact photo/audio/document originals and independent backups. Object keys and their ACLs must be scoped to workspace; SQL contains no raw clinical/photo bytes. External Sheets/Docs are projection/export adapters with separately tracked completion, never the only shared memory. The existing Institutional Post Office remains sole departmental dispatch authority.

**Identity and privacy**: `workspace` (PERSONAL, HOUSEHOLD, ORGANISATION) and `membership` with assigned roles; individual `person` as subject. An adult household member does not automatically gain access to another individual's health or sensitive records. A dependent child's guardian access requires explicit legal basis, granular per-subject policy and audit. The `003_life_core.sql` proof schema has **deny-by-default RLS for person identity** and workspace RLS on scoped records. This is NOT sufficient for production: the DB application role must not have SUPERUSER/BYPASSRLS; each transaction must bind an authenticated workspace ID and per-subject authorisation, preventing client-set session-variable spoofing. Add audited scope grants, invitations and verified revocation before exposing any data.

**Recovery/integration**: Preserve immutable UUID/digest, event key and original evidence ID. Each destination has its own operation status and idempotency key. A reported chicken use-by date is a provenance-marked claim, not verified inventory until the original source is checked and the specific batch/version is committed. When a Google Sheets export fails, the SQL fact remains queryable with its correct provisional status and an owner-visible unresolved projection. Post Office must independently prove delivery and signed actor receipt; never infer execution from a queue entry.

**Portability contract**: implement an open versioned schema, PostgreSQL migrations, JSON schema for neutral export bundles, per-workspace manifest, resource digests, attachment blobs, module versions, timezone/locale, original source and revisions; import into a clean instance with remapped local IDs and restored evidence checksums. Export only records within the actor's authorised scope and exclude encrypted keys/secrets. Tests must demonstrate two unrelated workspaces cannot list or mutate one another, and import produces equal semantic facts with preserved provenance. Test independent restore on another approved environment before claiming provider independence.

**No claims**: Schema is design review. No real multi-user auth, private object store, image/date extraction, import/export application, row-level permission grant service, Department adapter or production cutover is deployed. Do not submit real personal data to the public synthetic Railway server. Requires IT review, staged PostgreSQL test, verified backup and a narrow rollout decision.
